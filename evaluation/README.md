# Оцінювання вимови й нормалізації

`gold.tsv` перевіряє наголоси на регресійних прикладах. Це не випадкова вибірка й не незалежний тест якості. `normalization.tsv` — точний корпус правил для чисел, років, одиниць, дат та ідентифікаторів; перевірка запускається `node scripts/normalization-eval.mjs`.

Scorer зіставляє кожне повторне входження окремо. `TP` зараховується лише за повного
збігу очікуваних і фактичних наголосів; пропущені очікувані позначки дають `FN`, а
додаткові чи неправильні — `FP`. Невідповідність послідовності слів показується
окремо й не підміняється метрикою наголосів. Перевіряйте `dictionaryValidation` у
`report.json`: невалідні рядки зовнішнього словника пропускаються й лишаються
невирішеними замість автоматичного наголошення.

CI запускає `node scripts/eval.mjs --strict`: він вимагає 100% precision, recall не
нижче 96,9% і повного збереження слів. Пороги фіксують поточну відому похибку; їх
можна змінити разом із поясненням, якщо еталонний набір навмисно змінено.

## Як додавати приклади

- Зберігайте мінімальний вхідний текст і очікуваний результат в окремому рядку TSV.
- Додавайте пояснювальний тег (`year`, `unit`, `identifier` тощо), а не виводьте висновки з кількості прикладів.
- Рядки `gold.tsv` та `normalization.tsv` — тестові дані, а не підтвердження повної відповідності нормі. Для двозначної вимови додайте джерело й контекст у `lexicon/` або збережіть варіант як невирішений.
- Не переносіть фрази з робочого сценарію або приватного корпусу у публічний пакет без окремого рішення про їхню публікацію.

## Відкладена вибірка й аудіювання

Незалежний holdout має походити з окремих текстів, не використаних для написання правил. Фіксуйте версію пакета, рушій, точну модель/голос, налаштування, хеш вхідного й вихідного файлів та оцінку слухача. Порівняння аудіо має бути сліпим A/B: слухачеві не показувати, який варіант зроблений новою версією. Не змішуйте оцінки правильної вимови з якістю відеоряду, таймінгом або гучністю.

Схема для майбутнього журналу прослуховування: `sample_id`, `package_version`, `engine`, `voice_model`, `source_sha256`, `output_sha256`, `blind_label`, `stress_correctness`, `naturalness`, `notes`. На старті немає заповнених прослуховувань, тому жодних заяв про якість аудіо цей репозиторій не робить.
